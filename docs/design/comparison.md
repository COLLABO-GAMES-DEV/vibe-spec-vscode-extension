# 복제와 자유 편집

[문서 지도](README.md) · [결정 d30](decisions.md#d30)

## 사용 흐름

사이드바의 표·문서 우클릭 → **복제** → 새 이름 입력 → 같은 도메인에 새 파일 생성 → 새 탭 열기. 이름은 원본 이름 뒤 `_복사본`을 제안하고 충돌하면 숫자를 붙인다. Windows 파일명 규칙과 프로젝트 전체 표·문서 이름 중복 검사를 적용한다.

표는 데이터와 스키마를 각각 복제한다. 새 스키마 이름은 새 표 이름이며 기존 스키마와도 충돌하면 거절하고 다른 이름을 제안한다. 복제본의 열·타입·표시 순서 변경은 원본에 영향을 주지 않는다. 행 순서·Key·숫자 문자열·메모는 유지한다. 스키마 이름 포인터를 제외한 원문은 재직렬화하지 않는다.

문서는 Markdown 전체 바이트(BOM·CRLF·공백 포함)를 복사한다. 제목을 파일 이름에 맞춰 자동 변경하지 않는다. 이미지 파일은 같은 `documents/assets/`를 사용한다. 참조 열의 대상·자기 참조·문서 링크는 복사 전과 같은 대상을 가리키며 자동으로 복제본을 향하게 바꾸지 않는다. 원본을 가리키던 다른 파일도 변경하지 않는다.

복제는 파일에 저장된 내용을 사용한다. 원본 문서에 열린 미저장 초안이 있으면 먼저 저장하거나 버리도록 안내하며 복제를 중단한다. 표의 미완성 셀·행 draft도 먼저 확정하거나 취소하도록 한다.

## core·CLI와 보호

`duplicateResource(root, revision, kind, name, to)` 한 경로로 표·문서를 복제한다. CLI는 `duplicate <table|document> <name> --to <새 이름> --expect-revision <revision> [--dry-run] [--json]`이다. 잠금·revision·파일별 임시 교체·공통 검증은 기존 쓰기 계약을 사용한다. 이름 충돌은 덮어쓰지 않고 실패한다. 일반 내용 검증 오류는 복제 후 진단한다.

복제는 Git 커밋을 자동으로 만들지 않는다. 기존 사유와 함께 저장 흐름을 사용한다. 복제 전후에는 서로 독립된 파일이며 공통 수정 자동 상속·상태 기계·확정 합치기를 제공하지 않는다. 최종 사용할 내용과 참조 대상을 사용자가 일반 편집으로 정리한다.

## 이전 버전

기존 `plans/`는 파일 그대로 남기되 더 이상 읽기·쓰기·검증·fmt·이름 변경·저장 관리 대상이 아니다. 잘못된 옛 YAML도 표·문서를 여는 데 영향을 주지 않는다. `plan` 명령과 대안 `--target`은 명시적으로 거절한다. 기존 에이전트 스크립트를 위해 `--target base`만 무동작 호환 인자로 허용하고, 새 명령에는 요구하지 않는다. `import plan/apply`는 별개의 이관 기능이며 그대로 유지한다.

## 확인

표 원문·숫자·행 순서, 독립 스키마, 문서 원문과 이미지·링크, 이름 중복·잘못된 이름·stale revision·dry-run·삭제 보호를 검사한다. 실제 VS Code에서 메뉴 등록·도메인 내 생성·새 탭·초안 보호를 확인하고 Playwright에서는 복제 후 독립 편집과 A/B 조작 제거를 확인한다. 합성 데이터만 사용한다.
