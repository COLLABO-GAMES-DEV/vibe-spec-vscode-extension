## <a id="d30"></a>복제와 자유 편집 (2026-11-03)

- **무엇:** 전용 A/B core·CLI·화면·상태·확정 기능을 제거한다. 사이드바 표·문서 우클릭 메뉴에서 독립 복제하고 자유 편집한다. [복제 계약](comparison.md)을 따른다.
- **왜:** 비교와 선택에 별도 변경분·범위·상태 관리가 필요하지 않다.
- **버린 대안:** A/B 화면만 숨기고 변경분 엔진을 유지하는 방식.
- **기존 데이터:** `plans/`는 삭제·변환·자동 합치기하지 않는다. 관리·검증·fmt·이름 변경에서 제외하며 이전 Git 이력을 보존한다. 일반 표·문서로의 이관은 별도 사용자 결정이다.
- **대체:** 아래 d01·d02·d27과 d08·d12의 대안 합성/참조 갱신 조항을 대체한다. d21의 충돌 원문·출처 보존 원칙은 유지하되 질문은 일반 문서에 남긴다. 전달 상태(d10)는 자유 편집에서 최종본과 전달 범위를 정한 뒤 별도 설계한다.

## 검토 제안 — 아직 확정하지 않은 부분

- 일회성 이관은 원문 reader·CLI dry-run과 에이전트 스킬을 중심으로 운영한다. 승인된 이번 구현은 이 최소 도구를 추가하고 기존 import plan/apply와 화면을 유지한다. 이후 기존 importer를 얼마나 줄일지와 삭제는 사람 결정 사항이다.

## <a id="d29"></a>이름의 슬래시와 주소

- **무엇:** 제목·문단 이름표·Key·도메인 폴더 이름의 `/`는 원문으로 보존한다. 주소만 `./`로 시작하는 확장 형식을 쓰고, 각 단계에서 `~` → `~0`, `/` → `~1`로 바꾼다. 예: `./items/30~110`, `./guide/공격~1방어`. `/`가 없는 이름의 기존 주소는 그대로 쓴다. core가 생성·해석·비교를 담당한다.
- **왜:** 기존 주소 안의 `%2F`, `~1`, 전각 슬래시는 이미 문자로 쓰였을 수 있다. 첫 단계 `.`은 종전 리소스 이름으로 유효하지 않았으므로 `./`를 붙인 주소만 새 규칙으로 해석하면 유효한 기존 주소의 의미가 바뀌지 않는다.
- **버린 대안:** 표기를 무조건 치환하는 `%2F`·`\/`·전각 슬래시는 기존 이름 또는 Markdown 링크 디코딩과 충돌한다.
- **폴더:** 실제 디렉터리에 `/`를 넣을 수 없으므로 해당 폴더만 안전한 디렉터리명을 쓰고, 기존 `.gitkeep`에 원래 이름을 기록한다. 화면은 원래 이름, CLI는 core가 돌려주는 주소를 쓴다. 기존 빈 `.gitkeep`과 일반 디렉터리명은 그대로 해석한다. 이 경우에 한해 d16의 이름 매핑 제외를 대체하며 d24의 실제 폴더 원칙은 유지한다. 파일명인 테이블·스키마·문서 이름의 Windows 규칙은 유지한다.
