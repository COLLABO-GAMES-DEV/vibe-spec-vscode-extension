# 확정된 결정

[문서 지도](README.md)

새 결정으로 충돌하는 이전 결정을 대체했다. 상세 계약은 각 문서에 두고, 버린 방식은 아래 한 줄씩만 남긴다.

| 결정 | 무엇을 정했나 | 왜 | 버린 대안 |
| --- | --- | --- | --- |
| <a id="d01"></a>A/B 저장 | 기준안 위에 A/B/C의 대칭 변경분을 둔다. 공통 수정은 상속하고 선택 안을 기준안에 합치며 다른 안도 보관한다. | 쟁점만 diff에 남긴다. | 전체·작은 단위·범위 선택 스냅샷과 A를 B의 기준으로 삼는 방식. |
| <a id="d02"></a>기획 단위 | 여러 테이블·문서에 걸친 쟁점 하나와 대안들을 묶는다. | 관련 기획을 함께 검토·확정한다. | 행별 승인 단위와 리소스를 기획 단위마다 복제하는 구성. |
| <a id="d03"></a>Key와 이름 | 테이블마다 사용자가 고른 Key 열 정확히 하나가 필수·유일 기본키다. 테이블·스키마·문서도 이름으로 식별한다. | 원본에 진실이 하나이고 diff와 에이전트가 이름을 읽을 수 있어야 한다. | 불변 ID 체계와 Key의 이중 식별, key_ref. |
| <a id="d04"></a>번역 범위 | 번역 기능은 넣지 않는다. 필요한 문자열 테이블과 Key 연결은 사용자가 만든다. | 툴을 무겁게 하지 않는다. | 번역 워크플로·고정 언어 열. |
| <a id="d05"></a>숫자 | 문자열 원문을 저장하고 정밀도 상한을 두지 않는다. XLSX 이관의 제한된 정수 정규화 예외는 [d23](#d23)을 따른다. 비교는 기존 임의 정밀도 decimal 라이브러리를 쓴다. | 값과 입력 표현이 바뀌면 안 된다. | 부동소수 경유, 자체 계수·지수 모델, 저장 시 표기 정규화. |
| <a id="d06"></a>범용 도구 | 도메인 열·분류·숫자 규칙은 사용자 스키마가 선언한다. | 카탈로그는 예시이며 제품 기본 구조가 아니다. | 아이템 접두어·재화 범위·번역 구조 하드코딩. |
| <a id="d07"></a>불러오기 | 시트·Notion은 일회성 이관이고 이후 원본은 기획 레포다. | 별도 원본을 만들지 않는다. | 양방향·지속 동기화. |
| <a id="d08"></a>core와 UI | 포맷·읽기/쓰기·합성·검증을 core에 두고 CLI·익스텐션·에이전트가 공유한다. | 경로별로 규칙이 갈라지지 않게 한다. | UI·에이전트의 별도 합성·검증 구현. |
| <a id="d09"></a>git 화면 | 저장은 사유를 받아 커밋, 올리기는 push, 받은 변경은 pull·병합 화면으로 다룬다. | 비개발자가 기획 작업으로 이해하게 한다. | Git 명령 중심 UI와 A/B를 Git 브랜치로 표현하는 방식. |
| <a id="d10"></a>전달 상태 | 마지막 전달 태그와 현재 기준안을 비교한다. 미확정 대안은 전달 대상이 아니다. | 실제 전달 기록과 상태를 맞춘다. | 사람이 전달 여부를 찍거나 일반 push를 전달로 간주하는 방식. |
| <a id="d11"></a>경로 참조 | 이름/Key/열 코드명/제목을 단계로 연결한다. 이름에 /를 쓰지 않고 확장은 단계 추가로만 한다. | 사람이 읽는 경로의 해석을 유지한다. | 이스케이프 규칙과 기존 경로 의미 재해석. |
| <a id="d12"></a>이름 변경·조회 | rename이 기준안·모든 대안의 선언된 참조와 변경분 주소를 함께 고친다. 본문은 후보만 반환한다. where-used는 레포 안 조회다. 행 삭제 보호는 스키마 선언 시에만 한다. 테이블 삭제는 다른 테이블의 참조 선언이 있으면 막는다. | 필요한 연결만 자동 수정하고 불필요한 절차를 없앤다. | where-used 사전 확인 강제, 별칭·옛 이름 추적 장치. |
| <a id="d13"></a>규모·동시 수정 | 수천 행과 MVP 가상 스크롤을 목표로 한다. 사람 간 변경은 Git 병합, 같은 PC의 GUI/Codex 수정은 파일 경합으로 다룬다. | 실제 작업 경로에 맞춘다. | 실시간 다중 사용자 편집 설계와 동시 인원 질문. |
| <a id="d14"></a>단순한 구현 | 기존 라이브러리를 우선하고 단계별로 필요한 것만 구현한다. 파일별 임시 쓰기·교체, 잠금 파일, 쓰기 직전 revision 확인을 쓰고 실패 복구는 Git에 맡긴다. | 문제가 생기기 전 복잡한 장치를 만들지 않는다. | journal·recover 명령, 다중 파일 원자성 보장, 미래 기능 선구현·과도한 CLI. |
| <a id="d15"></a>화면에서 구조 편집 | 행·열·테이블을 화면에서 관리한다. Key 없는 행은 draft, 열 규칙 변경은 기존 값을 보존하고 오류로 표시한다. 행·열 작업은 되돌릴 수 있다. | 시트에 익숙한 기획자가 파일을 직접 고치지 않아도 된다. | 새 필수 열이나 타입 오류를 이유로 구조 편집 차단, 열 순서 변경에 따른 행 데이터 재작성. |
| <a id="d16"></a>플랫폼 공통 파일 이름 | 테이블·스키마와 2단계 문서 이름은 Windows에서도 쓸 수 있는 파일 이름으로 정한다. 한글과 원래 표기를 보존하며 대소문자만 다른 이름은 중복이다. 중복 이름 공간은 [d24](#d24)를 따른다. 잘못된 이름은 오류와 대체 이름 제안으로 알린다. 행 Key·열 표시명에는 파일명 제약을 적용하지 않는다. | Windows와 기본 macOS 파일 시스템에서도 같은 기획 레포를 사용할 수 있어야 한다. | OS마다 다른 이름 허용, 자동 이름 치환, 파일명과 기획 이름을 별도 매핑하는 방식. |
| <a id="d17"></a>개발용 내보내기 | 테이블마다 스키마 요약·전체 행·원본 revision을 마크다운으로 내보낸다. 출력 경로는 인자·설정으로 정하고 기본 출력은 커밋하지 않는 파생물이다. 정확한 값은 read --json으로 읽는다. | 개발 에이전트가 읽기 쉽고 YAML 원본은 하나로 유지된다. | 마크다운을 두 번째 원본으로 편집하거나 숫자·참조 값을 변환하는 방식. |
| <a id="d18"></a>기획 레포 위치 | 같은 게임 레포의 하위 폴더와 별도 레포를 모두 허용하고 .vibe-spec.json으로 고른다. | 팀의 저장소 배치를 강제하지 않는다. | 별도 레포 의무화, 같은 레포 push가 기획 커밋만 보낸다는 안내. |
| <a id="d19"></a>Git 인증 | 시스템 Git의 기존 gh·Git Credential Manager 등 자격증명을 사용하며 없으면 터미널 인증 방법을 안내한다. | 기존 로그인을 쓰고 인증 정보를 중복 관리하지 않는다. | 익스텐션의 별도 토큰 저장·로그인 구현. |
| <a id="d20"></a>여러 작업 폴더 | VS Code에 작업 폴더가 여러 개면 설정을 저장할 폴더를 사용자가 고른다. | 기획 루트 설정이 엉뚱한 프로젝트에 저장되지 않게 한다. | 첫 번째 작업 폴더를 묵시적으로 선택하는 방식. |
| <a id="d21"></a>불러온 기획의 상태 | 문제없는 부분은 기준안으로, 해석이 필요한 부분은 컨펌 전으로 둔다. 서로 다른 원본의 충돌은 출처를 가진 대칭 대안으로 남긴다. | 이관 과정에서 기획 판단을 몰래 확정하지 않는다. | 빈칸 추측 채움, 충돌값 자동 선택, 모든 원문을 확정으로 간주하는 방식. |
| <a id="d22"></a>문서와 원문 보존 | Notion처럼 블록으로 편집하되 Markdown 파일을 원본으로 쓰고, 편집한 블록 밖의 원문은 바이트 그대로 보존한다. 기존 제목 경로·문단 이름표·참조 추적·이름 변경·검증을 연결한다. | 기획자는 시각적으로 편집하고 에이전트와 Git은 원문을 안정적으로 읽어야 한다. | 편집기 JSON을 별도 원본으로 저장, 매 편집마다 전체 Markdown 재출력, 불변 블록 ID. |
| <a id="d23"></a>XLSX 정수 이관과 행 순서 | XLSX 숫자 셀의 값이 정수면 이관 때 정수 문자열로 정규화하고 원래 값·셀·출처 해시를 기록한다. integer Key를 허용하며 경로와 참조는 문자열 Key를 쓴다. 이관 행 순서와 이후 파일 순서를 보존하고 화면의 명시적 숫자 정렬만 보기 순서를 바꾼다. | 기획자·Codex·개발용 내보내기가 같은 값을 보며 이관 원본 순서가 불필요한 diff 없이 유지돼야 한다. | 화면에서만 .0 숨김, 텍스트·소수·날짜의 묵시적 정규화, fmt와 일반 편집의 자동 Key 정렬. |

| <a id="d24"></a>도메인 폴더와 단일 트리 | 테이블·문서를 실제 하위 폴더로 분류하고 사이드바에서 한 트리로 합친다. 기존 tables/·documents/ 루트를 유지하며 동일 상대 폴더를 하나의 도메인으로 표시한다. 이름은 폴더와 무관하게 프로젝트 전체에서 대소문자 무시 유일하며 참조에는 폴더를 넣지 않는다. | 기존 평면 기획과 공유 스키마·이미지 경로를 유지하면서 Git·에이전트에도 분류를 드러낸다. | 가상 폴더 메타데이터, 폴더를 참조 주소에 추가, 기존 파일을 새 공통 루트로 강제 이관. |
| <a id="d25"></a>문서 탭과 편집 UX | 기획 트리에서 문서 파일마다 독립 탭을 연다. 문서 편집 동작은 [d26](#d26)을 따른다. 표·문서·폴더 이름 목록은 숫자 인식 자연 정렬하고 파일 순서는 보존한다. | 파일과 화면의 대응을 명확히 하고 Notion에 익숙한 기획자의 편집 동작을 줄인다. | 별도 문서 사이드바·탭 내부 문서 목록, 블록별 상시 버튼, 이름의 단순 문자열 정렬. |

| <a id="d26"></a>문서 전체 편집과 저장 시 원문 보존 | 문서 전체를 BlockNote 인스턴스 하나로 편집하고, 사유와 함께 저장할 때 원문 블록과 비교해 변경 부분만 직렬화한다. 미변경·이동 블록은 원문 조각을 재사용한다. 지원 밖 구문은 편집기 안의 원문 블록으로 편집한다. | 라이브러리의 자연스러운 입력·슬래시·드래그·되돌리기를 유지하면서 Markdown 원본을 보존한다. | 블록마다 편집기를 붙이기, 포커스 이탈마다 파일 반영, 별도 적용 버튼·초안 상자, 저장 때 전체 Markdown 재출력. |

## 검토 제안 — 아직 확정하지 않은 부분

- 일회성 이관은 원문 reader·CLI dry-run과 에이전트 스킬을 중심으로 운영한다. 승인된 이번 구현은 이 최소 도구를 추가하고 기존 import plan/apply와 화면을 유지한다. 이후 기존 importer를 얼마나 줄일지와 삭제는 사람 결정 사항이다.
- 충돌 칸의 기준값 우선순위 `게임 반영값 > 구조화 원본 > 본문 표`는 제안이다. 아직 이를 자동 적용하지 않는다. 이미 있는 기준값과 각 출처를 보존하고 판단을 기다린다.
