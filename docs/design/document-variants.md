# 문서 A/B 대안 편집

[문서 지도](README.md) · [기획과 대칭 대안](variants.md) · [문서 원문 보존](documents.md) · [d14](decisions.md#d14)

**사용자가 승인한 첫 구현 범위다.** 이름표 문단·섹션·문서 전체의 교체를 지원한다. 목록·표 개별 선택은 제외하며, 테이블 대안의 기존 파일은 그대로 읽힌다.

## 최소 범위

기존 기획 단위 안에서 문서의 특정 부분을 A/B로 편집·비교하고, 사람이 고른 안만 확정한다. 상태·출처·선택·보관은 [기존 계약](variants.md)을 재사용한다. 출처 충돌은 [d21](decisions.md#d21)을 따르며, 기준값을 정하기 위해 출처 순위를 만들지 않는다.

편집 대상은 기준안 또는 `기획/대안`을 항상 표시한다. A/B 모두 기준안 위의 변경분이다. 문서 생성·문서 전체 삭제·대안별 파일 이름 변경·서로 다른 기획의 동시 조합은 첫 구현에서 제외한다. 기존 테이블 변경분과 문서 변경분은 한 기획의 같은 대안에 함께 둘 수 있다.

## 주소와 변경 범위

불변 ID나 저장된 줄 번호·블록 순번을 새로 만들지 않는다. 기존 경로로 범위를 지정한다.

- `문서/제목/…/이름표`: 이름표가 붙은 문단 하나. 이름표 자체는 주소이므로 일반 본문 편집으로 지우지 않는다.
- `문서/제목/…`: 그 제목과 하위 제목을 포함한 섹션. 다음 같은 수준 또는 상위 제목 직전까지다.
- `문서`: 문서 전체. 제목 없는 문서이거나 전체가 쟁점일 때만 사용자가 명시적으로 선택한다.

최소 구현은 **선택한 범위의 교체**만 저장한다. 섹션 안에서 문단·목록·표·이미지를 추가·삭제·이동하는 것은 BlockNote의 기본 편집이며, 결과는 그 섹션의 교체로 표현한다. 원문 문단 하나만 쟁점이면 기존의 선택적 이름표를 먼저 기준안에 붙여 좁은 범위를 고를 수 있다. 목록·표에는 현재 이름표를 붙일 수 없으므로 해당 섹션을 범위로 고른다. 이 제약을 숨기거나 이름표 문법을 임의로 확장하지 않는다.

동일 대안에서 범위가 겹치면 거절한다. 상위 섹션과 그 안의 문단을 각각 덮어쓸 수 없다. 선택한 주소 자체의 제목/이름표 변경·삭제와 섹션 밖으로의 이동은 첫 구현에서 막고 기준안 이름 변경 기능으로 안내한다. 범위 안의 하위 제목 변경은 합친 문서의 중복·링크 검증을 거친다. 편집 결과가 상위 범위를 탈출하는 제목 수준을 만들면 저장 전에 거절하고 초안을 보존한다.

**승인된 제한:** 섹션은 그 안의 모든 내용을 덮어쓰므로, 나중에 기준안에서 같은 섹션의 다른 문단을 고쳐도 자동 상속하지 못한다. 이전/현재/대안을 보여주는 충돌 검토가 필요하다. 범위 밖 수정은 자동 상속한다. 이름 없는 목록·표의 개별 주소는 후속 설계에서만 다룬다. 내용 해시·위치 추측으로 조용히 대응시키는 장치는 넣지 않는다.

## 저장 형식

`plans/<기획>/<안>.yaml`에 선택적 `documents`와 `document_base_values`를 추가한다. `set/add/remove`의 기존 테이블 의미는 바꾸지 않는다. 아래는 합성 예시다.

```yaml
documents:
  rules/전투/재시도: "재시도는 3회까지 허용한다."
document_base_values:
  rules/전투/재시도: "재시도는 2회까지 허용한다."
sources: []
```

B안은 같은 주소에 다른 원문을 둔다. 값은 Markdown 문자열이며 편집기 JSON을 저장하지 않는다. `document_base_values`는 최초 수정 시 core가 기록하고 대안을 고칠 때 다시 찍지 않는다. 이름표 문단의 주소용 주석은 범위 밖에 두며, 섹션은 대상 제목부터 해당 섹션의 마지막 블록 끝까지를 저장한다. 범위 전후의 구분 공백·문서 BOM은 기준안에 남는다. 실제 경계는 core의 원문 위치로만 계산한다.

문자열은 CRLF·공백·역슬래시를 그대로 복원할 수 있는 YAML 이스케이프를 사용한다. 변경하지 않은 범위는 대안 파일에 저장하지 않는다. 같은 범위 안의 미변경 블록도 편집기 전체 직렬화로 재출력하지 않고 기존 원문 조각을 재사용한다. 대안에 기록된 섹션은 내부 원문을 포함하므로 큰 섹션의 최초 diff가 커지는 비용은 남는다. 이 최소 형식은 일반 Markdown 패치 엔진을 만들지 않는다.

## 읽기·쓰기·원문 보존

기준안과 대안을 합치는 로직은 core 한 곳에 둔다. CLI와 host는 `target`을 전달하고 합쳐진 문서·블록·진단·revision을 받는다. Webview나 에이전트가 변경분을 직접 합치지 않는다. 문서 내 표 셀 링크도 같은 target의 테이블 값을 표시한다.

문서 전체를 BlockNote 하나로 보여주되 대안에서는 선택한 범위만 편집 가능하게 한다. 다른 범위는 기준안에서 상속한 내용임을 표시한다. 그곳을 편집하려면 범위를 명시적으로 추가해야 하며 자동으로 문서 전체를 쟁점으로 확대하지 않는다. 선택한 범위의 블록 대응·변경 부분 직렬화에는 [기존 저장 방식](documents.md#라이브러리-경계)을 재사용한다.

저장 시 core는 합쳐진 문서의 일시적인 블록 순번과 revision을 확인하고 새 범위 원문을 계산해 **대안 YAML만** 쓴다. 기준안 Markdown은 확정 전까지 바뀌지 않는다. 무변경 저장은 파일 바이트가 같아야 한다. 저장 사유·여러 초안 일괄 반영·파일 반영과 Git 커밋 실패 구분은 기존 흐름을 따른다. 대상/기획/안 전환 전에 미저장 초안을 저장하거나 버릴지 명시적으로 고르게 한다.

최소 CLI 확장은 `document read --target <plan>/<variant>`, `plan variant`의 문서 변경분 입력, `document edit --target <plan>/<variant>`를 사용한다. 파일 쓰기는 기존 dry-run·잠금·revision 계약을 따른다. `document_base_values`를 에이전트가 입력하거나 직접 고치지 않는다. init의 AGENTS.md에 실제 지원 명령과 범위 제한을 안내한다.

## 기준안 변경·참조·확정

- 변경 범위 밖의 기준안 수정은 즉시 상속한다. 범위 안이 달라지면 이전 기준 원문·현재 기준 원문·대안 원문을 보여준다. 범위를 찾을 수 없거나 주소가 중복이면 합치기 오류다. 자동 재배치·재기준화는 하지 않는다.
- 기준안과 각 대안을 따로 검증한다. 문서 경로·이름표·깨진 링크·원문 경계와 테이블 참조 모두 같은 core를 쓴다. 경계가 달라져 두 블록이 합쳐지거나 코드 fence가 다른 범위까지 삼키는 변경은 거절한다.
- where-used는 기준안/어느 대안에서 발견했는지 구분한다. 이름 변경은 기준안과 모든 대안의 주소·구조화 링크·과거 기준 원문 속 구조화 링크를 함께 고친다. 자유 텍스트와 sources의 역사적 원문은 자동 치환하지 않는다. 대안 하나의 의미 변경을 다른 대안의 이름 변경으로 전파하지 않는다.
- 비교 화면은 기준안/A/B 열과 범위별 Markdown diff를 제공한다. 범위 안에서도 실제 바뀐 줄만 강조하고 각 출처를 펼쳐 볼 수 있게 한다. 기준안 변경 경고와 링크 오류를 별도로 표시한다.
- 확정 미리보기에는 선택한 안이 현재 기준안의 어떤 내용을 대체하는지 보여준다. 사람이 고르면 동일 revision에서 선택한 변경분만 합친다. 바깥 원문 바이트는 그대로 두며 다른 대안과 출처는 기존 규칙대로 보관한다. 파일별 쓰기 실패는 기존 changed 목록과 Git 복구를 따른다.
- 저장·확정 중 외부 변경이 생기면 거절하고 초안을 남긴다. 재읽기 후 사용자가 세 원문을 확인하기 전 오래된 대안을 조용히 덮어쓰지 않는다. 전달 상태는 확정된 기준안만 비교한다.

## 검사 범위

core/CLI에서 무변경 바이트 동일, 부분 수정·추가·삭제·이동, BOM/CRLF/공백/한글/이모지, 원문 블록·반복 내용, 범위 중첩·탈출·삭제, 이름 변경/where-used, 각 조합 검증, 현재 기준 변경과 stale, 테이블+문서 동시 확정을 검사한다. 미변경 구간은 문자열 의미가 아니라 바이트로 비교한다.

Playwright는 단일 편집기에서 target·편집 범위 표시, 초안 보존, 나란히 비교, 기준안 변경 경고, 저장 전환·확정을 검증한다. 실제 VS Code에서는 독립 탭·파일 감시·여러 초안 저장과 커밋을 검증한다. Windows 검사도 출시 전 기존 CI 정책을 따른다. 합성 데이터로 검사하며 실제 이관 데이터는 제품 레포에 포함하지 않는다.

## 화면 보조 기능과 제한

문서에서 새 기획·대안을 만들거나 기존 안을 선택한 뒤 범위를 체크한다. 미저장 초안이 있으면 전환을 막고 저장 또는 명시적인 초안 버리기를 제공한다. 확정은 기획 비교 화면에서 수행한다. 새 범위 선택은 세션 상태이며 실제 변경을 저장할 때 변경분에 기록된다. 저장된 범위는 화면에서 체크 해제하지 않으며, 제거하려면 CLI plan variant 입력에서 해당 documents 경로를 제외한다.

기준안의 이름 변경과 같은 대안 파일을 동시에 수정하는 다중 초안은 한 번에 반영하지 않고 별도 저장을 안내한다. 자동 병합으로 한쪽 변경을 잃지 않기 위한 제한이다. 범위 안의 구조 변경은 core가 다시 검사하며 범위를 벗어나면 파일을 쓰지 않고 초안을 유지한다.
