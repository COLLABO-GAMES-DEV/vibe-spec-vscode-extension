# 문서와 블록 편집

[문서 지도](README.md) · [원문 보존 결정](decisions.md#d22) · [이름·경로](format.md) · [단순한 구현](decisions.md#d14)

## 범위와 원본

`documents/[도메인/]<문서 이름>.md`가 유일한 본문 원본이다. 파일명·테이블과의 이름 충돌은 기존 이름 규칙을 따른다. 그림은 `documents/assets/`의 파일로 보관하고 Markdown에서는 `assets/<파일명>`으로 연결한다. 그림을 DB나 편집기 JSON 안에 넣지 않는다. 문서 생성·블록 추가/수정/삭제·이름 변경·이미지 추가를 core가 처리한다. 이번 편집 대상은 기준안이다. 문서 변경분을 A/B로 편집하는 UI·전달 태그·범용 Notion 변환기는 이번 범위에 넣지 않는다. 이관의 미해결 문제는 기존 컨펌 전 기획 단위에 출처와 질문을 남긴다.

문서를 읽거나 `fmt`를 실행해도 본문을 재출력하지 않는다. UTF-8 원문, BOM, 빈 줄, 들여쓰기, 줄 끝 공백, 개행 종류, 마지막 개행 유무를 보존한다. 화면에서 새로 쓰는 문서·블록은 LF를 사용한다. 파일을 입력받아 생성할 때는 입력 파일의 바이트를 보존한다. 기존 CRLF 문서를 일부 편집할 때도 건드리지 않은 구간은 그대로다. Markdown은 `.gitattributes`의 `documents/**/*.md -text`로 Git의 자동 개행 변환에서 제외한다. YAML의 LF 계약은 바뀌지 않는다.

## 블록 경계와 쓰기

CommonMark + GFM 파서가 반환한 원문 위치로 최상위 블록을 구분한다. 제목, 문단, 목록 전체(중첩 포함), 표 전체, 인용 전체, 코드, 구분선이 편집 단위다. 목록 항목·표 셀을 고치면 그 목록·표 블록만 다시 쓴다. 이미지 단독 문단도 한 블록이다. 블록 사이 공백과 문서 앞뒤 구간은 편집 대상에 포함하지 않는다.

블록 위치/순번은 해당 revision에서만 유효한 편집 주소다. 파일에 ID나 위치를 저장하지 않으며 공개 참조로 쓰지 않는다. 쓰기는 기존 잠금·revision 확인·파일별 임시 교체를 따른다. 편집기에서 열었다 닫기, 선택만 이동하기, 변경 없는 저장은 바이트 무변경이다. 저장 시점의 문서 전체 순서와 읽은 revision의 원본 블록을 비교해, 변경한 블록만 직렬화하고 바뀌지 않은 블록은 원문 조각을 사용한다. 삭제는 원래 범위만 제거하고, 이동은 원문 조각을 옮긴다. 주변 공백·BOM·개행은 재출력하지 않는다. 새 블록 사이 필요한 구분자만 추가한다.

원문을 안전하게 표현할 수 없는 HTML, 수식, 깨진 표, 알 수 없는 확장은 원문 블록으로 보존하고 확인 경고를 표시한다. 원문 보기·명시적 원문 편집이 가능하며, 이를 시각 편집기에 넣어 몰래 정규화하지 않는다. 리치 편집이 지원하는 구문도 지원하지 않는 내부 요소를 포함하면 해당 블록은 원문 모드로 둔다. HTML을 실행하지 않는다.

## 라이브러리 경계

core는 `remark-parse`·`remark-gfm`의 위치 정보를 사용한다([공식 문서](https://github.com/remarkjs/remark/tree/main/packages/remark-parse)). 화면은 문서 전체에 BlockNote 인스턴스 하나를 사용한다([d26](decisions.md#d26)). 입력·추가·삭제·이동·드래그·슬래시/사이드 메뉴·되돌리기는 라이브러리의 기본 동작에 맡긴다. Markdown으로 표현할 수 있는 블록·서식을 스키마로 선택하고, 지원 밖 구문은 편집기 내부의 원문 블록으로 표시한다. 원문 블록의 입력은 Markdown 문자열 그대로 저장하며 HTML을 실행하지 않는다.

BlockNote의 [Markdown 출력은 손실 변환](https://www.blocknotejs.org/docs/features/export/markdown)이므로 저장 때 문서 전체를 직렬화하지 않는다. 열 때 원문 블록과 대응하는 편집기 블록·내용을 메모리에 기록하고, 저장 때 내용과 위치를 비교한다. 편집기 내부 ID도 메모리에서만 대응에 사용할 수 있다. 목록·인용 하나가 편집기의 여러 블록으로 나뉘면 원문 그룹 단위로 비교한다. 그룹이 갈라지거나 대응이 애매하면 그 부분만 변경된 것으로 처리한다. 반복된 같은 내용으로 다른 원문을 잘못 재사용하지 않는다. 파일에 ID나 편집기 JSON은 추가하지 않는다.

core가 받는 저장 입력은 최종 순서의 블록 목록이다. `{original: i}`는 읽은 revision의 원문 블록 재사용, `{original: i, markdown: "…"}`는 변경, `{markdown: "…"}`는 추가이며 누락된 원본은 삭제다. 중복·범위 밖 원본 인덱스는 거절한다. Webview는 비교·변경 부분 직렬화만 담당하고, 원문 끼워넣기·경계 검사·참조 갱신·쓰기·검증은 core가 맡는다. 이 저장 입력은 통신용이며 별도 기획 파일 형식이 아니다.

## 경로·연결·이름 변경

기존 `문서/제목/하위 제목`과 문단 바로 앞의 `<!-- name: 이름표 -->`를 그대로 사용한다. 제목은 표시되는 텍스트를 경로로 삼으며 같은 부모 아래 제목·이름표 중복과 `/` 포함은 오류다. 이름표는 뒤따르는 문단에만 붙고 별도 본문으로 렌더링하지 않는다. 제목 계층의 단계가 건너뛰면 실제 상위 제목으로 연결한다. 문서 이름만으로 문서 전체를 가리킬 수 있다.

Markdown 링크의 목적지에 기존 경로를 쓴다. 예: `[가격](shop-products/bundle_01/price)`, `[획득](economy/재화/획득)`. 공백이 있는 경로는 표준 Markdown의 `<...>` 목적지 표기를 사용한다. 링크의 제목·서식과 목적지는 구분한다. 문서 안의 셀 링크는 현재 값과 경로를 표시하고 클릭하면 해당 표·칸으로 이동한다. 값은 문자열 그대로 표시하며 본문에 값을 복사해 저장하지 않는다. 외부 http(s)/메일 링크와 로컬 이미지 경로는 기획 경로와 구분한다.

where-used는 구조화된 링크와 자유 본문 후보를 나누어 반환한다. 테이블·Key·열·문서·제목·이름표 rename은 목적지의 해당 경로 부분만 수정하고 나머지 원문을 유지한다. 이름 변경은 참조된 제목을 시각 편집기에서 수정할 때도 같은 core 경로를 거친다. 일반 텍스트·코드 예제의 이름은 후보만 반환한다. 깨진 링크·삭제된 대상은 검증 오류다. 문서 링크를 이유로 스키마에 없는 행 삭제 보호를 만들지 않는다.

## 화면과 CLI

사이드바의 [단일 기획 트리](extension.md#도메인-트리)에서 파일마다 문서 이름을 제목으로 한 독립 탭을 연다([d25](decisions.md#d25)). 같은 문서를 다시 열면 기존 탭을 보이며 다른 문서의 draft는 유지한다. 탭 안에는 문서 목록을 두지 않는다. 문서 단위 이름 변경·삭제·사용처는 제목 옆 `⋯`와 트리 컨텍스트 메뉴로 제공한다.

문서는 처음부터 하나의 연속 편집 영역이다. 블록별 편집 활성화·포커스 이탈 적용·적용 버튼·초안 상자를 두지 않는다. 편집 중 변경은 메모리에 유지하고, `Ctrl/Cmd+S` 또는 기존 “변경 사유와 함께 저장”을 실행하면 사유를 받은 뒤 열린 문서들의 변경을 모아 core에 한 번에 반영하고 커밋한다. 취소하거나 사유가 비어 있으면 파일에 쓰지 않는다. 여러 문서는 동일한 기준 revision으로 한 번에 검증해, 첫 문서 저장이 다른 문서의 revision을 낡게 만드는 일을 피한다. 서로 다른 기준의 draft나 외부 변경은 저장 전에 거절한다. 표의 미완성 입력 규칙은 유지한다.

저장 실패 시 편집 내용은 유지한다. 파일 반영 뒤 Git 커밋이 실패한 경우에는 파일 반영과 커밋 실패를 구분하며 다음 저장에서 다시 커밋할 수 있다. 저장 성공 후 새 원문을 기준으로 갱신하되 불필요하게 편집기 인스턴스·선택·기본 되돌리기 기록을 다시 만들지 않는다.

첫 H1이 있으면 본문의 그 제목을 한 번만 보여주고 파일 이름은 탭에만 표시한다. H1이 없을 때만 파일 이름을 화면 제목의 대체값으로 쓴다. 파일 이름과 공개 참조 경로는 바꾸지 않는다. 블록 간격은 기본 편집기 수준으로 좁히고, 바깥에 추가 버튼용 빈 행이나 블록별 편집 상자를 쌓지 않는다. 원문 이름표는 해당 문단에 연결해 보존하고, 문서·제목·이름표 관리와 셀 참조 값 표시는 기존 core 경로를 사용한다.

외부 파일 변경은 감시해 새로 읽는다. 편집 중인 문서와 열 때의 revision은 유지하며, 저장이 거절되면 이유·현재 원문을 보여준다. 사용자 확인 없이 외부 변경 위에 덮어쓰지 않는다. 문서·링크·검증은 core 결과를 받아 표시한다. 이미지는 허용된 프로젝트 내부 파일을 host가 Webview URI로 전달하며 외부 주소를 자동으로 가져오지 않는다.

최소 CLI는 `document list/read/create/edit/delete`, `document image`와 기존 `read`, `where-used`, `rename document|heading|tag`, `validate`를 사용한다. create는 Markdown 파일 입력, edit는 블록 순번 기반 작업 JSON을 받는다. 쓰기는 `--target base --expect-revision`과 `--dry-run`을 지원한다. AGENTS.md에는 블록 순번을 revision 밖에 보관하지 말 것과 전체 문서 재직렬화 금지를 적는다.

## 저장·검사·실전 이관

문서와 로컬 그림은 기획 관리 파일로 Git 저장에 포함한다. Markdown 충돌은 Git의 줄 단위 병합을 먼저 쓰고 남은 충돌은 기존 파일 선택 화면에서 기준/내 변경/받은 변경을 고른다. 블록용 병합 엔진은 만들지 않는다.

- core: 원문 재읽기·무변경 저장·fmt 바이트 동일, 전체 순서 입력의 추가/삭제/이동·반복 내용·여러 문서 동시 저장, 한 블록 밖 바이트 동일(한글/이모지/BOM/CRLF 포함), 제목/태그 경로·중복·링크 검증, rename 목적지 최소 수정, stale 거절, 이미지 경로 경계.
- CLI: 실제 프로세스로 생성·블록 편집·rename·where-used·validate·Git 저장을 검증하고 일반 테이블·기획 대안 회귀 검사를 유지한다.
- Playwright: 브라우저 가짜 host도 실제 core를 사용한다. 단일 편집기 연속 입력·사유 저장·사유 취소·무변경 저장, 기본 슬래시/사이드 메뉴·드래그·추가·이동·삭제·되돌리기, 표/체크/이미지, 원문 보존, 셀 참조 표시, 외부 변경 draft 보존을 검사한다.
- 실제 VS Code: 단일 트리·자연 정렬·문서별 독립 탭·재열기·이름 변경·파일 감시·문서 간 경로 이동·사유 저장 시 여러 문서 flush와 커밋을 API 수준으로 확인한다. 기존 Linux·Windows CI 여섯 작업에 포함한다.
- 시험 폴더의 보존된 Notion 34개 원문을 일회성 스크립트와 CLI로 이관한다. 확실한 페이지/그림 링크만 목적지를 바꾸고 변경 구간·출처·해시를 기록한다. 나머지 바이트와 원본 파일은 보존한다. 깨진 링크·지원 불가 요소·판단이 필요한 자기 링크는 컨펌 전 기획에 기록한다. 기존 importer는 유지한다.
