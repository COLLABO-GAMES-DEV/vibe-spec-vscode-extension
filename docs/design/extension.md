# 익스텐션

[문서 지도](README.md) · [git 화면](decisions.md#d09) · [규모와 동시 수정](decisions.md#d13)

## MVP 화면

- 설치 후 기획 폴더를 선택하거나 초기화하고 프로젝트 루트에 경로를 저장한다. 여러 작업 폴더의 선택은 [d20](decisions.md#d20)을 따른다.
- 왼쪽 사이드바는 테이블·문서를 합친 기획 트리·오류·저장·올리기를, 중앙 Webview는 표 편집을 담당한다. **개발용 내보내기**는 core의 [마크다운 출력](cli.md#개발용-내보내기)을 실행하고 출력 폴더·오류 수를 알린다.
- **수천 행을 위한 가상 스크롤을 MVP에 포함한다.** 키보드 이동·여러 칸 붙여넣기·ref 선택·오류 위치 이동을 제공한다.
- 숫자 칸은 원문 문자열 입력이다. 표시명은 사용자 label을 쓰되 명령·진단은 경로의 열 코드명을 함께 보여준다.
- Webview는 VS Code 없이 브라우저에서 실행 가능하게 하고 host 메시지 어댑터만 바꿀 수 있게 한다. 테스트 방식은 [testing.md](testing.md)에 둔다.

## 행·열·테이블 관리

[화면 구조 편집 결정](decisions.md#d15)에 따라 행 머리 메뉴에서 위/아래 삽입과 선택한 여러 행 삭제를 제공한다. Key 없는 새 행은 입력 위치의 draft이며 확정 후 파일 끝에 추가하고 현재 보기 순서의 해당 행을 선택한다. 위/아래 삽입은 입력 위치이며 파일 끝에 추가됨을 안내한다. 선언된 삭제 보호에 걸리면 사용처를 보여준다.

헤더 메뉴에서 왼쪽/오른쪽 열 추가, 설정 변경, 삭제를 제공한다. 추가 설정은 표시명·코드명·타입·필수 여부이며 enum은 선택지, ref는 대상 테이블을 받는다. 새 열은 기존 행에서 비어 있고 필수 오류는 칸에 표시한다. 타입 변경도 값을 변환하지 않는다. 코드명은 rename, 표시명은 스키마 수정으로 처리한다. 삭제는 데이터 손실 확인과 사용처를 표시하며 Key 열은 지울 수 없다. 헤더 드래그로 표시 순서를 바꾼다. 세부 저장 규칙은 [포맷](format.md)에 둔다.

사이드바의 새 테이블은 이름과 Key의 표시명·코드명만 받아 스키마와 빈 표를 함께 만든다. 이름 입력에서 `/`와 중복을 알린다. 테이블 메뉴의 이름 변경은 rename을 사용하고, 삭제는 다른 테이블의 참조 선언이 있으면 사용처를 보여주며 막고 그 외에는 확인받는다. 함께 지우는 스키마는 해당 테이블만 사용하는 경우로 한정한다.

행·열 편집의 되돌리기/다시 하기는 화면의 메모리 기록을 사용한다. 외부 변경과 충돌하면 덮어쓰지 않는다. 표의 선택·복사·찾기·보기용 정렬/필터는 파일 순서를 바꾸지 않으며 Key/헤더 고정과 열 너비 조절을 제공한다. 셀 확정은 클릭·Enter·Tab, 취소는 Esc이며 미완성 숫자는 draft로 남긴다.

## 편집·저장·올리기

편집은 core로 파일에 반영하고 검증 결과를 표시한다. 일반 검증 오류는 반영을 막지 않으며 삭제 보호는 [결정](decisions.md#d12)에 따른다. 저장은 기획 루트의 관리 파일 변경만 비어 있지 않은 사유로 커밋하고, 올리기는 push한다. 사이드바에 편집 중(draft) / 저장 전 / 올리기 전 / 올리기 완료를 표시한다. 표의 미확정 draft는 먼저 확정하거나 취소하게 한다. 문서는 [전체 편집기 저장 계약](documents.md#화면과-cli)에 따라 사유를 받은 뒤 문서 변경을 모아 파일에 반영하고 커밋한다. 파일 반영·로컬 커밋·원격 전송 결과를 구분하고 인증·네트워크 실패가 로컬 저장을 취소하지 않음을 알린다. force push는 제공하지 않는다.

[기획 레포 위치](decisions.md#d18)에 관계없이 push는 브랜치의 커밋들을 보낸다. 다른 코드 변경이 섞인 레포라면 올라갈 커밋 범위를 보여주며 기획 파일만 전송한다고 안내하지 않는다.

인증은 [시스템 Git 인증 결정](decisions.md#d19)을 따른다. GitHub HTTPS 인증 실패에는 `gh auth login`과 `gh auth setup-git`을 안내한다.

같은 PC의 Codex 파일 수정은 감시로 감지한다. 같은 칸을 편집 중이면 로컬 입력과 새 파일 값을 보여주고 다시 읽게 한다. 잠금·revision 확인과 실패 복구는 [아키텍처](architecture.md)에 따른다.

## pull과 충돌

다른 사람의 변경은 받아오기로 받는다. 미저장 파일이 있으면 먼저 저장하게 한다. Git 병합 후 표 이름·Key·열 코드명으로 행 차이를 보여주고 충돌 행의 기준 / 내 변경 / 받은 변경 중 하나를 고르게 한다. 다른 행과 겹치지 않는 칸은 자동 병합한다. 스키마·해석 불가능한 표는 파일 단위로 보여주며 기획 폴더 밖이나 일반 파일이 아닌 충돌은 Git에서 해결하게 한다. 이름 변경을 과거 이름과 자동 연결하지 않는다. 병합 후 validate를 실행해 옛 이름 참조·중복 Key 등을 표시한다.

## 최소 2단계

기획 목록은 사이드바에만 두고 기획중·컨펌 전·확정을 표시한다. 가운데 비교 패널에는 선택한 기획의 제목·상태와 기준안/A/B 비교·확정 화면만 표시한다. 사이드바에서 다른 기획을 선택하면 같은 패널을 바꾸며, 미선택 상태에는 사이드바 선택 안내를 표시한다. 쟁점 경로의 칸만 보이며 바뀐 값과 추가·삭제를 강조한다. 값·경고·검증 결과는 core에서 받아 그리고, 기존 표 편집기는 편집 대상이 기준안임을 표시한다.

기획중/컨펌 전 상태 변경과 선택 안 확정만 화면에 제공한다. 확정 전 선택한 안과 기준안 합치기를 확인하며, 화면을 연 revision이 달라지면 덮어쓰지 않고 다시 비교하게 한다. 확정 후 선택 안과 보관된 대안을 표시한다. 대안 작성은 CLI를 사용하고 문서 편집기는 후속 범위다. 변경분 포맷과 보관 규칙은 [기획·대안](variants.md)을 따른다.

문서 목록·블록 편집기·원문 확인·문서 외부 변경 처리는 [문서 화면 계약](documents.md#화면과-cli)을 따른다.

표의 기본 순서는 파일 순서다. integer Key를 포함한 숫자 열을 명시적으로 정렬하면 decimal 라이브러리로 숫자 값을 비교하며 파일 순서·값은 바꾸지 않는다.

Key 기반 충돌 병합은 로컬 파일의 생존 행 순서를 유지하고 받은 쪽에만 있는 새 행을 받은 순서로 뒤에 붙인다. 행 삭제 되돌리기는 외부 행 순서를 바꾸지 않고 원래 뒤따르던 생존 행 앞에 복구한다.

## 도메인 트리

[d24](decisions.md#d24)의 도메인을 `기획` 트리 하나로 표시하고 별도 `테이블`/`문서` 섹션은 두지 않는다. 기획 비교·검증·저장/올리기 섹션은 유지한다. 폴더 아래 표(`table`)와 문서(`file-text`)를 아이콘으로 구분하고 오류 수를 보여준다. 폴더는 `folder`, 검토 기획은 `git-compare`, 확정 기획은 `archive`로 구별한다. 새 폴더·표·문서는 트리 제목의 `+` 하나에서 고른다. 툴팁은 만들 수 있는 대상을 명시하고 메뉴에는 생성 위치를 보여준다. 폴더 컨텍스트 메뉴도 같은 생성 명령을 사용한다. 불러오기·내보내기는 제목의 추가 메뉴로 옮겨 기본 툴바 아이콘을 줄인다. 폴더 메뉴에서 생성·이름 변경·빈 폴더 삭제·이동, 표/문서 메뉴에서 다른 폴더로 이동을 제공한다. 이동은 우선 메뉴로 구현하며 드래그 전용 계층은 만들지 않는다. 대상 폴더와 실제 이동 파일을 확인할 수 있게 한다.

트리와 리소스 선택 목록의 이름은 [d25](decisions.md#d25)에 따라 숫자를 인식해 정렬한다(예: `1`, `6`, `11`, `100`). 폴더 우선 그룹 안에서도 같은 이름 비교를 사용한다. 이는 조회·화면 순서이며 저장 파일/행 순서를 변경하지 않는다. 문서 탭의 편집 동작은 [문서 화면 계약](documents.md#화면과-cli)에 둔다.

폴더 접기/펼치기는 기획 루트와 상대 폴더 경로를 키로 workspaceState에 보존한다. 기획 원본에 UI 상태를 기록하지 않는다. 같은 이름의 표/문서 탭은 폴더 이동 뒤에도 유지하며 새 revision을 받는다. 전체 관리 하위 폴더의 생성·삭제·재생성과 CLI 변경을 감시한다. 데이터가 바뀐 draft에 대한 기존 revision 거절 규칙도 유지한다.

## 화면 시각 체계

문서·표·비교 화면은 VS Code의 편집기·입력·버튼·선택·경고 테마 색을 따른다. 저장·확정은 주요 버튼으로, 찾기·되돌리기·새로 읽기 등 보조 작업은 낮은 강조로 구분한다. 문서 제목·본문 위계와 간격을 정리하고 표의 헤더·행 경계를 구분하되 가상 스크롤의 공유 열 너비·행 높이와 편집·저장 계약은 유지한다.
