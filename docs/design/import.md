# 불러오기

[문서 지도](README.md) · [일회성 이관](decisions.md#d07)

## MVP: CSV/TSV/XLSX

기존 파서를 이용해 조사·매핑 미리보기·적용 순으로 진행한다. Google Sheets는 파일로 내려받아 사용한다. 실제 시트의 첫 행과 A열은 비어 있고, 헤더는 B2:E2, 데이터는 B3부터다. 이 위치를 다른 시트에 하드코딩하지 않는다.

사용자는 원본 열을 스키마의 코드명에 연결하고 Key 열 하나를 지정한다. 현재 시트의 매핑 예시:

```yaml
schema: items
header_row: 2
start_column: B
data_start_row: 3
columns:
  B: key
  C: source
  D: lore
  E: note
```

- 선행 여백은 선택 범위에서 제외하되 원본 셀 좌표를 유지한다. 내부 빈 셀·열을 압축하지 않는다.
- Key/Source/Lore/Note는 문자열이다. Source는 한국어 아이템 이름 원문이며 접두어로 분류 열을 만들지 않는다.
- 빈/중복 Key, 중복 헤더, 숨김·병합 셀, 수식과 지원하지 않는 서식·이미지는 미리보기에서 알린다. 누락값에 0을 채우지 않는다.
- 다른 숫자 시트도 원문 문자열을 보존한다. XLSX 저장 값과 화면 표기가 다르면 선택할 표현을 보여주며, 부동소수로 변환한 값으로 원문을 복원했다고 주장하지 않는다.
- 기존 라이브러리로 손실 없이 읽을 수 없는 셀은 미지원으로 보고한다. 전용 숫자 엔진이나 수식 계산기를 만들지 않는다. 원본 프로그램이 이미 잃은 정밀도는 복원할 수 없다.
- 참조 열은 대상 표의 Key에 매핑한다. 별도 식별자를 발급하지 않는다.
- 적용 전 미리보기에서 대상 파일·제외/변환 내용을 보여준다. 다시 불러온 파일을 기존 값과 자동 동기화하지 않는다.
- 쓰기는 공통 잠금·revision 확인을 사용하고 중간 실패는 Git으로 되돌린다.

MVP 구현은 UTF-8 CSV/TSV와 XLSX를 읽는다. `inspect → plan → apply`의 [CLI](cli.md)와 익스텐션이 같은 core를 쓴다. 기존 표는 새 Key를 추가하며 덮어쓰지 않는다. 적용 직전에 원본 해시도 확인한다. XLSX 날짜·오류·캐시 없는 수식·라이브러리 간 제어문자 해석이 다른 문자열 등 원문을 보장할 수 없는 셀은 미지원이다. 서식 표시 후보는 계산값임을 표시하고 안전한 후보가 없으면 저장 원문을 선택하게 한다.

## 3단계: Notion

내보낸 문서·표를 이름과 제목 경로로 변환한다. 지원하지 못하는 블록·관계는 알린다. 세부 변환 규칙은 3단계에서 설계한다.

## 최소 원본 도구와 에이전트 스킬

[검토 제안](decisions.md#검토-제안--아직-확정하지-않은-부분)에 따라 기존 단순 표 경로는 유지한다. 새로운 `vibe source inspect <file> --json`은 CSV/TSV/XLSX의 좌표·저장 문자열·수식·병합 범위·수 서식·hyperlink 대상을 내보낸다. 숫자를 Number/Date로 만들지 않으며 날짜도 저장 문자열과 서식을 따로 반환한다. 표시값 계산이나 표·Key 선택은 하지 않는다. XML 문자 정규화나 SpreadsheetML escape처럼 그대로 옮길 수 없는 경우는 issues를 보고 원본을 유지한다.

같은 명령의 Notion ZIP 경로는 UTF-8 Markdown/CSV 원문과 파일 해시를 읽고, 파일명 끝의 원본 32자리 ID로 링크를 연결한다. 이 ID는 출처 식별이며 기획의 Key를 대체하지 않는다. 데이터베이스는 같은 ID의 `_all.csv`를 우선하되 다른 파일도 목록에 남긴다. 이미지·기타 파일은 목록·해시로 보존 대상을 알리고, 원본 ZIP은 유지한다. 범용 문서 변환·수식 계산·노션 동기화는 하지 않는다.

`init`은 `.agents/skills/vibe-import/SKILL.md`를 만들고 AGENTS.md에서 연결한다. 스킬은 조사 → 구조·Key·타입 제안 → 새 판단이 필요한 질문 → dry-run → CLI 적용 → 검증·출처 보고를 안내한다. 이미 승인된 범위는 재확인하지 않는다. [Codex 공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills)의 저장소 위치와 name/description frontmatter를 따른다. 다른 에이전트도 같은 문서를 명시적으로 읽을 수 있다.

`edit/apply --dry-run`은 같은 core 준비·검증 경로를 실행하고 파일을 반영하지 않는다. 현재 revision과 예정 파일·내용·진단을 반환하며, 실제 적용 때 같은 revision으로 다시 검사한다. 출처 기록은 원본 file/sourceHash와 sheet/cell 또는 page/path, raw 값, 대상 경로·적용 revision의 JSON 데이터로 남긴다. 별도 동기화 엔진이나 복구 journal은 만들지 않는다.

[d21](decisions.md#d21)에 따라 문제마다 기획 이름·질문·컨펌 전 상태·각 대안의 값과 출처를 기록한다. 최초 시험의 결정 목록 JSON은 [기획 단위](variants.md)로 옮긴다. 실제 경로가 없는 문제는 질문·출처만 보관하며 주소나 값을 지어내지 않는다. 기준안 우선순위와 의미가 불확실한 값은 사람이 정한다.

## XLSX 정수 정규화·추론·출처

[d23](decisions.md#d23)의 예외는 XLSX 숫자 셀에만 적용한다. raw는 원문을 유지하고 별도 normalizedInteger 후보를 제공한다. 날짜 서식 셀은 숫자 직렬값이어도 제외한다. 캐시가 있는 숫자 수식 셀은 기존 수식/캐시 경고를 유지하며 재계산하지 않는다. 이관할 때 정확한 값이 정수인 숫자 셀은 정수 문자열을 사용한다. 이 규칙은 계산된 표시 후보 선택보다 우선한다. 소수·텍스트·날짜와 CSV/TSV에는 정규화를 적용하지 않는다. Number를 거치지 않는다.

빈 셀을 제외한 최종 이관 값이 모두 정수 문법이면 integer 타입을 제안한다. 빈 열·미지원 셀을 포함하는 열은 text로 둔다. 추론은 제안이고 사용자가 명시한 기존 스키마·타입을 덮어쓰지 않는다. Key도 integer를 선택할 수 있다. 정규화로 Key가 겹치면 합치거나 덮어쓰지 않고 중복 오류로 적용을 막는다.

정규화로 원문이 바뀐 셀은 `imports/<기록 SHA-256>.json`에 파일·원본 해시·시트·좌표·열·raw/value·매핑·이전 revision과 함께 남긴다. 이 파일은 기획 저장 대상이며 fmt는 재작성하지 않는다. dry-run에서 예정 기록을 확인하고 실제 적용 시 표·스키마와 같은 잠금/revision 검사 아래 파일별로 쓴다. 저널이나 원복 명령이 아니며 실패 복구는 Git이다.

행은 원본 시트 순서로 이관한다. 기존 표에 추가할 때는 기존 행 뒤에 원본 순서로 추가한다. fmt·일반 편집은 파일의 순서를 유지한다. 재이관으로 기존 표를 덮어쓰는 제품 명령은 추가하지 않는다. 이번 시험 폴더는 승인된 일회성 재이관으로 처리하고 원래 상태와 Key 변경 대응을 보고서에 남긴다.

## 도메인 목적지

이관 mapping은 선택적 `folder`로 tables/ 아래 도메인 경로를 지정한다. 생략하면 기존 평면 동작이다. 기존 스키마는 schemas/ 전체에서 이름으로 찾고 새 스키마는 schemas/에 만든다. 하위 폴더의 기존 표도 이름 중복·참조 검사에 포함한다. 세부 규칙은 [도메인 포맷](format.md#도메인-폴더)을 따른다.
