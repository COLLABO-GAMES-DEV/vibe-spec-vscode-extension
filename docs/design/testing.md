# 테스트 전략

[문서 지도](README.md) · [MVP 완료 흐름](architecture.md)

모든 층은 architecture.md의 같은 완료 흐름을 사용한다. 작은 고정 fixture와 수천 행 fixture(예: 5,000행)를 두되 서로 다른 제품 시나리오를 만들지 않는다.

일반 push·PR은 Linux에서 core·CLI, 실제 VS Code, Playwright 1회를 독립 job으로 실행한다. Windows 전체 검사는 `v*` 태그 배포 및 수동 실행에서만 수행한다. Playwright는 CI에서 실패 재시도 없이 1회 실행한다. 한 층의 실패가 나머지 검사를 건너뛰게 하지 않는다. Windows에는 PowerShell 5.1/7, 한글·공백 경로, 다른 드라이브의 기획 폴더, BOM 입력, autocrlf와 LF 저장, 다른 프로세스가 파일을 열어 교체가 거절되는 경우를 포함한다. 운영체제 전용 검사는 해당 러너에서 실제로 실행한다. Windows Git e2e는 여러 native Git 호출을 묶은 CLI 한 번에 60초를 허용한다. 제품의 개별 로컬 Git 제한(30초)보다 테스트가 먼저 프로세스를 죽이지 않게 하며 검증 assertion과 실패 재시도 정책은 완화하지 않는다.

| 층 | 확인할 계약 | 실행 |
| --- | --- | --- |
| core — Vitest | 변경 없이 읽고 다시 쓰면 바이트 동일, 숫자 원문 보존, 한 칸 수정은 한 줄 교체 diff | PR CI |
| CLI e2e — **주력** | 실제 CLI를 임시 기획 레포에서 실행. 이관·편집·검증·저장·전송·병합 전체 | **모든 PR CI** |
| 익스텐션 통합 — @vscode/test-cli | 진짜 VS Code에서 명령, 사이드바 트리, 파일 감시, 저장을 API 수준으로 확인 | PR CI |
| Webview — Playwright | VS Code 없이 브라우저에서 가짜 메시지를 주입. 가상 스크롤·입력·붙여넣기·숫자·오류 표시 확인 | PR CI |

## CLI e2e의 필수 구성

- 임시 로컬 bare 레포를 원격으로 두고 작업 클론 두 개를 만든다. 실제 Git과 실제 CLI를 사용한다.
- B2 헤더 이관, 공통 셀 편집, 사유 커밋, push·pull, 서로 다른 행 병합, 같은 칸 충돌과 해결을 재현한다.
- 한 클론에서 Key를 rename하고 다른 클론에서 옛 Key 참조를 추가한 뒤 병합한다. 병합 뒤 validate가 깨진 참조를 잡는지 확인한다.
- 선언된 삭제 보호의 거부와, 보호를 선언하지 않은 삭제 후 검증 오류를 구분한다.
- 행·열 되돌리기와 외부 변경 충돌, 스키마 변경 후 validate·fmt, 테이블 생성·참조 갱신·삭제 보호를 확인한다. GUI의 빈 Key draft·열 순서·사용처·삭제 확인은 Playwright, 사이드바 명령과 감시는 실제 VS Code에서도 확인한다.
- 숫자는 긴 정수·소수, 앞/끝자리 0, 부호·지수 표기를 왕복시킨다. 임시 파일 교체 중 실패 후 Git으로 마지막 커밋에 돌아갈 수 있는지도 확인한다.

한 줄 diff는 일반 칸의 값 변경을 뜻한다. Key 변경으로 행이 이동하거나 여러 참조가 함께 바뀌는 경우는 별도 rename 시나리오로 판정한다. GUI/Codex가 같은 PC에서 읽은 오래된 revision으로 덮어쓰지 않는지도 확인한다.

[수동 Codex runner](../codex-acceptance.md)는 현재 init의 AGENTS.md와 동봉 CLI를 사용해 실제 데모의 독립 복사본에서 과제를 실행한다. 숫자 수정·행 추가·Key/참조 rename·의도한 오류 수정의 결과와 원본 불변을 판정한다. Codex 과제에도 같은 이관·편집·이름 변경 흐름을 사용한다. 작업 후 필요한 경우 두 번째 클론의 옛 참조 병합을 이어서 재현한다. 모델의 설명이 아니라 예상 변경 범위, 숫자 원문, 실제 CLI 진단으로 성공을 판정한다.

도구 근거: [VS Code 확장 테스트](https://code.visualstudio.com/api/working-with-extensions/testing-extension), [Playwright](https://playwright.dev/docs/intro).

## 최소 2단계

기준안 단독과 각 대안의 참조·유일성, 공통 변경 상속, 이전/현재/대안 값 경고, 행 삭제 후 오류, 이름 변경의 보관본 갱신을 core와 CLI에서 확인한다. 확정은 선택한 변경만 합치고 모든 대안 파일을 보관한다. 화면은 기준안/A/B 비교·상태·확정·오래된 revision 거절을 검사한다. 실제 사업 판단은 시험으로 대신 확정하지 않으며, 원본 충돌은 컨펌 전으로 유지하고 독립 시험 기획에서 확정 흐름을 검증한다.

문서 기능의 바이트 보존·블록 편집·링크·실전 이관 검사는 [문서 검사 계약](documents.md)을 따른다. 기존 Linux·Windows 실행 행렬에 함께 포함한다.

도메인 회귀: 평면/중첩 기획 읽기·편집·rename·where-used·검증·이관·내보내기·Git 저장/병합, 이동 전후 YAML/Markdown 바이트와 참조 동일, 전역 이름 충돌·Windows 폴더 이름·빈 폴더 보존·비어 있지 않은 삭제·stale·심볼릭 링크 경계. Playwright는 하위 폴더 데이터의 표/문서 편집·연결, 실제 VS Code는 단일 트리·폴더 메뉴·접힘 유지·하위 파일 감시를 검증한다. 검사 범위는 유지하고 실행 시점은 위 정책을 따른다.
