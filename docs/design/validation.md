# 검증 규칙

[문서 지도](README.md) · [도메인 비강제](decisions.md#d06) · [조회와 삭제 보호](decisions.md#d12)

## MVP

| 검사 | 내용 |
| --- | --- |
| 파일·스키마 | YAML 문법, 중복 mapping key, 스키마 이름·선언된 열·지원 타입 |
| 기본키 | 스키마의 Key 열이 정확히 하나이며 각 행에서 필수·유일·비어 있지 않음 |
| 이름·경로 | / 금지, 경로 단계 해석, 테이블/문서 이름의 모호성, 예약된 * Key |
| 값 | 선언된 타입·required·nullable·enum·범위·추가 unique |
| 참조 | ref 열의 Key가 스키마의 대상 테이블에 존재하는지 |
| 숫자 | 문자열 원문 유지; 범위·수치 유일성은 decimal 라이브러리로 비교 |

오류에는 파일·경로·규칙·메시지를 반환한다. 줄 번호는 위치 안내일 뿐 주소가 아니다. where-used의 자유 텍스트 결과는 관계 오류가 아닌 조회 후보다.

[플랫폼 공통 파일 이름 결정](decisions.md#d16)에 따라 테이블·스키마 파일의 금지 문자·예약 이름·파일명 길이를 검사한다. [도메인 결정](decisions.md#d24)에 따라 표·문서 이름은 프로젝트 전체에서, 스키마 이름은 schemas/ 전체에서 대소문자 중복을 검사한다. 폴더는 같은 논리 부모 아래의 이름을 검사한다. 충돌 비교에는 Unicode NFC를 사용하되 저장된 이름 표기는 바꾸지 않는다. `NAME_INVALID`·`NAME_COLLISION` 오류에는 사용할 수 있는 이름 제안도 표시한다(예: `CON` → `CON_`, 중복된 `Items` → `Items_2`). 행 Key·열 표시명에는 이 파일명 규칙을 적용하지 않는다. 문서 파일에도 같은 검사를 적용한다.

## 검증과 작업 차단

검증은 진단과 CI 판정이다. 일반 편집·저장에 별도의 승인이나 전체 검증 통과 절차를 강제하지 않는다. **내용 편집을 사전 차단하는 보호 규칙은, 스키마에 on_delete: restrict가 선언된 참조의 대상 행 삭제뿐**이다. 이 설정이 없으면 삭제 후 남은 깨진 참조를 검증 오류로 보고한다.

이름 규약에 맞지 않거나 이미 쓰는 이름과 충돌하거나 대상을 특정할 수 없는 명령 인자는 잘못된 요청으로 거절한다. 잠금 실패·쓰기 직전 revision 불일치·I/O 실패도 작업 실패로 보고한다. 이를 새로운 기획 승인 규칙으로 만들지 않는다.

다른 브랜치에서 옛 이름 참조가 들어오면 병합 후 검증한다. 존재하지 않는 대상으로 판정하면 충분하며 자동 별칭 추적·수정은 하지 않는다. 텍스트 병합 성공을 데이터 검증 성공으로 표시하지 않는다.

## 이후 단계

최소 2단계는 [대안 포맷](variants.md)의 문법·대상 경로·기준값 기록과 기준안 단독/기준안+각 대안의 검증을 추가한다. 덮어쓴 기준값 변경은 경고이고, 수정 대상 삭제·추가 Key 충돌은 오류다. 보관된 안은 문법과 이름 변경 대상에 남지만 현재 기준안에 재적용하지 않는다. 문서 제목·이름표·경로·지원 불가 블록 검증은 [문서 계약](documents.md)을 따른다.
