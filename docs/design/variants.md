# 기준안과 대안 — 2단계

[문서 지도](README.md) · [저장 결정](decisions.md#d01) · [기획 단위](decisions.md#d02)

이번 최소 2단계는 테이블 변경분·기획 상태·비교·확정을 구현한다. 문서 변경분은 [문서 A/B 편집](document-variants.md)에 정의한다. 전달 태그 UI는 후속 범위다.

## 변경분과 읽기

기획 단위와 A/B는 이름으로 구별한다. 예를 들어 `plans/s-grade/A.yaml`, `B.yaml`을 둔다. A/B 모두 기준안 위의 변경분이며 합친 값은 core가 제공한다. 익스텐션·에이전트는 직접 합치지 않는다.

사용자 스키마가 `grade-rates` 표의 `grade`를 Key로, `chance_percent`를 decimal로 선언했다고 하자. 기준안 S행의 값은 `"0.4"`다. A안 예시:

```yaml
set:
  grade-rates/S/chance_percent: "0.5"
base_values:
  grade-rates/S/chance_percent: "0.4"
```

B안은 같은 경로의 값을 `"0.8"`로 둔다. 경로는 [참조 규약](format.md)을 그대로 쓰고, 과거 기준값도 해당 경로로 기록한다. 필드만 저장하므로 그 값을 수정할 때 쟁점 줄만 바뀐다.

## 파일과 연산

기획을 만들 때 `plans/<이름>/_plan.yaml`을 만들고 각 대안은 같은 폴더의 `<안 이름>.yaml`에 둔다. 파일 이름에는 [공통 규칙](decisions.md#d16)을 적용하며 `_plan`은 예약한다.

```yaml
title: "S등급 확률 검토"
status: "review"
question: "S등급 확률을 0.5%와 0.8% 중 어느 쪽으로 할까요?"
sources: []
```

상태는 `draft`(기획중), `review`(컨펌 전), `approved`(확정)이다. 확정하면 메타데이터에 `selected: "A"`를 기록한다. 출처 `sources`는 원본 파일·해시·좌표·원문을 담는 목록이며 문자열·참/거짓·null·배열·객체를 쓴다. 숫자 좌표도 `"111"`처럼 문자열로 전달하며, 숫자 입력을 조용히 형변환하지 않고 거절한다. 도메인 의미를 검사하지 않는다. 아직 구조를 결정하지 못한 문제는 질문·출처만 있는 기획으로 보관할 수 있다. 대상 경로나 값을 만들어 채우지 않는다.

변경분의 `set`은 셀 경로, `add`와 `remove`는 행 경로를 사용한다. 예시의 상품 열은 사용자 스키마가 선언한 것이다.

```yaml
set:
  grade-rates/S/chance_percent: "0.5"
add:
  shop-products/new_bundle:
    price_currency: "currency_gold"
    price: "12.5000"
remove:
  - "shop-products/old_bundle"
base_values:
  grade-rates/S/chance_percent: "0.4"
  shop-products/old_bundle:
    sku: "old_bundle"
    price_currency: "currency_gold"
    price: "10.00"
base_missing:
  - "shop-products/new_bundle"
sources: []
```

`add`의 Key는 경로에서 얻으므로 본문 필드에 다시 적지 않는다. `base_values`와 `base_missing`은 core가 처음 변경 경로를 추가할 때 기록하며 기존 변경분을 고칠 때 갱신하지 않는다. `null`과 필드 부재는 구별한다. 삭제는 당시 행 전체를 비교한다. 동일 행의 추가·삭제·필드 수정이 겹치는 입력은 거절한다. 기존 필드 변경은 해당 줄만 바뀐다.

## 편집·검증·확정

- 편집 대상은 기준안인지 어느 기획 단위의 안인지 명시한다. 기준안의 비쟁점 수정은 모든 대안에 반영된다.
- 기준안의 덮어쓴 필드가 바뀌면 이전 기준/현재 기준/대안 값을 보여준다. 경로 대상이 사라지면 검증 오류다.
- 기준안 단독과 기준안+A, 기준안+B를 각각 검증한다. 스키마의 참조·유일성은 각 합친 결과에 적용한다.
- 이름 변경 명령은 기준안과 모든 대안의 참조·변경 주소·기준값 주소를 함께 고친다. 보관된 안도 현재 레포의 파일이면 대상이며, 과거 Git 커밋을 다시 쓰지는 않는다.
- 상태는 사람이 기획중·컨펌 전·확정을 정한다. 확정하면 고른 변경분을 기준안에 합치고 나머지 안은 삭제하지 않고 보관한다.
- 확정된 기획과 대안은 그대로 보관하고 다시 편집·확정하지 않는다. 보관본의 문법은 계속 검사하지만 현재 기준안에 다시 합쳐 검증하지 않는다. 이미 합쳐진 행 추가를 재적용할 수 없기 때문이다. 과거 합친 결과는 Git으로 확인한다.
- 일반 값 검증 오류는 기존 쓰기 계약대로 반영 후 보고한다. 존재하지 않는 수정 대상·중복 추가·삭제 보호처럼 합칠 수 없는 변경은 확정하지 않는다. 기준값 변경 경고는 이전/현재/대안 값을 보여주며 오류와 구분한다.
- 이전 이름 추적이나 독립적인 역사 재현 장치를 추가하지 않는다. 과거 내용은 Git 이력으로 본다.

## 화면과 전달

[익스텐션](extension.md)은 기준안/A/B를 열로 놓고 쟁점 칸만 강조한다. 저장·읽기 대상도 이름과 경로로 표시한다.

[전달 결정](decisions.md#d10)에 따라 마지막 전달 태그의 기준안과 현재 기준안을 비교한다. 대안만 수정하면 기준안 전달 상태는 바뀌지 않고, 확정되어 기준안이 바뀌면 전달 후 수정됨이 된다. 태그 발행·전달 UI는 2단계에서 설계한다.
