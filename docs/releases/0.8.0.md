# 0.8.0 — 문서 A/B 대안 편집

문서 전체를 BlockNote로 편집하며, 이름표 문단·섹션·문서 전체 중 명시한 범위만 대안에 저장한다. A/B 모두 기준안 위의 대칭 변경분이다. 사유 저장은 대안 YAML만 바꾸며 기획 비교에서 사람이 확정할 때 기준안 Markdown에 합친다. 목록·표 개별 선택은 제외한다.

## 사용

1. 문서를 열고 새 기획·대안을 만들거나 기존 대안을 선택한다.
2. 쟁점 범위를 선택해 편집하고 변경 사유와 함께 저장한다. 범위 밖은 기준안에서 상속한다.
3. 기획 비교에서 기준안/A/B와 바뀐 줄을 확인한다. 기준안이 달라졌으면 이전 기준·현재 기준·대안을 함께 검토한다.
4. 고른 안을 확정한다. 다른 안과 출처는 보관한다. 문서에서 계속 편집하려면 대상을 기준안으로 바꾼다.

기존 문서 CLI는 `document read/edit --target <plan>/<variant>`를 지원한다. 범위 선언은 `plan variant`의 `documents`를 사용한다. `document_base_values`는 core가 캡처하며, 에이전트나 Webview가 합치기·검증을 따로 구현하지 않는다.

## 보존과 실패 처리

- 무변경 저장은 대안 파일의 주석까지 바이트 그대로 둔다.
- 범위 밖 Markdown, BOM, CRLF, 공백은 원문 조각으로 보존한다. 범위 끝에 새 블록을 추가할 때도 바깥 구분자를 LF로 바꾸지 않는다.
- 겹친 범위, 사라진 대상, 주소를 바꾸거나 섹션을 탈출하는 편집은 거절한다.
- stale revision이면 초안을 유지한다. 파일 반영 성공과 Git 커밋 실패를 구분한다.
- A/B가 서로 다른 범위(예: 섹션과 그 안의 문단)를 선택해도 각 비교 칸은 core가 합친 원문이다.
- where-used·이름 변경은 대안 경로와 구조화 링크에도 적용한다. 역사적 출처 원문은 자동 치환하지 않는다.

## 검사 기록

합성 데이터만 사용했다. 실제 기획 이관·수정은 진행하지 않았다.

- core·CLI: 774 통과, 7 건너뜀. 실제 CLI 프로세스의 읽기·dry-run·편집·stale·확정 포함.
- 타입 검사와 전체 빌드 통과.
- 브라우저 전체 162 통과 후, 범위 경계 보완과 줄별 diff 추가에 대한 문서·대안 관련 46개 재검사 통과. Playwright retries=0.
- 실제 VS Code: 단일 폴더 66개 + 다중 폴더 5개 통과. 실제 Webview 메시지로 대안 저장·기준안 감시·확정을 검사했다.
- 기존 폴더 감시 검사에서 삭제 후 재생성된 imports 하위 폴더를 관측하지 못한 로컬 실패가 1회 있었다. 이벤트·파일 상태 진단을 추가한 실행에서는 재현되지 않았다. 관련 assertion·타임아웃·재시도 정책은 완화하지 않았으며 해결됐다고 단정하지 않는다.
- 공개 전 현재 트리의 실제 데이터 지문·개인 경로/이메일·비밀값 검사에서 발견 0건. 서드파티 저작권 고지는 유지한다.

최종 커밋의 Linux push 검사와 Windows 수동 검사 결과는 [Check 실행 기록](https://github.com/COLLABO-GAMES-DEV/vibe-spec-vscode-extension/actions/workflows/check.yml)에서 확인한다. 이번 작업은 태그·Release·Marketplace 게시를 실행하지 않는다.

## 설치와 제한

설치 파일은 `artifacts/vibe-spec-0.8.0.vsix`다. VS Code 확장 화면의 Install from VSIX로 설치한다. 라이선스는 UNLICENSED다.

저장된 범위를 제거하려면 CLI plan variant 입력에서 해당 문서 경로를 제외한다. 기준안 이름 변경과 같은 대안 파일에 대한 편집이 한 저장에 겹치면 별도 저장하도록 안내한다. 섹션을 쟁점으로 고른 경우 그 안의 다른 기준안 변경도 자동 상속하지 않고 세 원문 비교 대상으로 둔다.
