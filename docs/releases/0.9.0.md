# 0.9.0 — 이름 안의 슬래시

제목·문단 이름표·Key·도메인 폴더 이름의 `/`를 원문 그대로 유지한다. 설계는 [d29](../design/decisions.md#d29), 주소 계약은 [format](../design/format.md#확장-주소)에 있다.

## 주소 선택

**`./`로 확장 주소를 구별하고 `/` → `~1`, `~` → `~0`으로 표현한다. 기존 유효 주소의 의미를 바꾸지 않으면서 원래 이스케이프 문자와도 충돌하지 않기 때문이다.**

| 원문 이름 | 주소 |
| --- | --- |
| Key `30/10` | `./items/30~110` |
| Key `30~110` | `items/30~110` |
| Key `30%2F10` | `items/30%2F10` (CLI 원문 주소) |
| 제목 `공격 / 방어` | `./guide/공격 ~1 방어` |
| 이름표 `기본/값~1` | `./guide/공격 ~1 방어/기본~1값~01` |

Markdown 목적지에는 기존 URI 규칙도 적용된다. 예를 들어 문자 `%`는 `%25`로 적고 공백이 있으면 `<...>`로 감싼다. 기존 링크의 `%2F` 구분자 해석은 유지한다. 셀·ref·apply JSON의 별도 `key`·rename `--to` 값에는 주소 이스케이프를 하지 않는다. 대안 파일에는 core가 반환한 canonical 주소를 쓴다.

## 변경 범위

- core의 주소 생성·분해·상위 범위 비교를 공통화했다. read, where-used, rename, 검증·삭제 보호, 표와 문서 대안, 화면 참조 이동과 오류 위치가 이를 사용한다.
- 슬래시가 든 Key의 추가·수정·이름 변경·되돌리기와 대안 추가/삭제/확정을 지원한다. 참조 칸은 원래 Key 문자열이다.
- 제목·이름표의 주소만 바뀐다. Markdown 무변경 저장, 선택 범위 밖 바이트 보존, 외부 변경 진단은 유지한다.
- 폴더는 실제 디렉터리를 유지한다. OS가 허용하지 않는 `/`를 포함하는 이름에 한해 `.gitkeep`에 원래 이름을 기록하고 디렉터리는 안전하게 인코딩한다. 기존 문자 `~1` 폴더와 충돌하면 물리 이름에 접미사를 붙여 구별한다. 화면은 원래 이름, CLI는 `folder list`가 반환한 주소를 쓴다. 생성·이동·이름 변경·삭제·이관·Markdown 내보내기가 같은 대응을 사용한다.
- `vibe init`의 AGENTS.md와 vibe-import 스킬에 주소·원문 인자 구분을 추가했다. 기존 기획 폴더의 안내 파일은 자동으로 덮어쓰지 않는다.
- 테이블·스키마·문서 **파일 이름**과 열 코드명의 기존 규칙, 예약 Key `*`는 유지한다. Marketplace 게시·실제 데이터 이관은 하지 않는다.

## 검사와 원문 확인

합성 회귀 자료에는 `/`, `~1`, `%2F`, 전각 슬래시, 한글, BOM·CRLF를 포함한다. core·CLI에서는 기존 주소와의 구별, 구조화 참조·사용처·이름 변경, 대안 범위·확정·원문 보존, 삭제 보호·되돌리기, 폴더 충돌·이관·내보내기를 검사한다. Playwright는 원래 제목과 Key 표시, 대안 편집·충돌 경고, 셀 이동과 오류 표시를 실제 core로 확인한다. 잘못된 확장 주소는 원문과 오류를 보존하고, 문서 화면을 비우거나 관련 없는 이름 변경을 막지 않는다. 이 두 문제는 각각 실패를 재현한 회귀 검사로 고쳤다. 실제 VS Code에서는 원래 폴더명 표시·문서 범위 열기·폴더 이름 변경을 확인한다.

시험 폴더는 읽기 전용으로 확인했다. 전체 파일 **776개**의 검사 전후 SHA-256이 동일했다. 슬래시 제목 오류 **3개가 사라졌고**, 이번 범위 밖 링크 미연결 오류 **1개**와 기존 원문 모드 경고 **18개**는 남았다. 기획 데이터·원문·시험 보고 파일은 변경하지 않았다.

로컬 검사: core·CLI **781 통과 / 7 플랫폼 조건 제외**, Playwright 전체 **166 통과** 후 잘못된 주소 수정의 관련 회귀 **3 통과**(재시도 0), 실제 VS Code **72 통과**(단일 작업 공간 67 + 다중 작업 공간 5). 최종 VSIX에서 추출한 CLI로 init·폴더/표/문서 생성·확장 주소 읽기·validate·fmt를 별도로 통과했다.

전체 CI 결과는 [Check 실행 목록](https://github.com/COLLABO-GAMES-DEV/vibe-spec-vscode-extension/actions/workflows/check.yml)에서 이 변경 커밋의 Linux push 검사와 Windows 수동 검사로 확인한다. 화면 검사의 재시도는 0이다. 설치 파일은 `artifacts/vibe-spec-0.9.0.vsix`이며 사용자가 직접 게시한다.
