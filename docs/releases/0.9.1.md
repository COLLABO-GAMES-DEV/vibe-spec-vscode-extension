# 0.9.1 — 선택한 기획에 집중하는 화면

## 화면

- 가운데 기획 비교 패널의 전체 기획 목록을 제거했다. 선택한 제목·상태, 비교와 확정 화면만 표시한다. 선택하지 않았거나 기획이 없는 경우에는 사이드바 선택 안내를 표시한다.
- 사이드바 선택은 기존 패널을 바꾼다. revision 경고, 다시 읽기, 상태 변경, 확정 확인과 변경분 보관 동작은 유지한다.
- 문서의 제목·본문 위계, 편집 대상 영역과 툴바 간격을 정리했다. BlockNote 메뉴도 VS Code의 메뉴·입력·선택 테마 색을 사용한다.
- 표의 보조 버튼 강조, 헤더와 행 경계, 선택 영역, 필터 입력을 정리했다. 공유 열 너비, 가상 스크롤 행 높이, 편집·저장·원문 값은 바꾸지 않았다.
- 문서는 `file-text`, 표는 `table`, 폴더는 `folder`, 검토 기획은 `git-compare`, 확정 기획은 `archive` 아이콘으로 구별한다.

설계는 [익스텐션 화면](../design/extension.md)에 반영했다. 파일 포맷과 core 쓰기 계약은 변경하지 않았다.

## 검사

합성 데이터만 사용한다. Playwright에 기획 45개가 있어도 중앙에 목록을 만들지 않는 검사, 미선택 안내, 사이드바 메시지에 따른 선택 전환을 추가했다. OS 테마와 VS Code 테마가 반대인 경우에도 문서·표·비교가 VS Code 라이트·다크 색을 따르는지 검사한다. 실제 VS Code에서는 사이드바 두 항목이 같은 비교 패널을 바꾸는지와 문서 아이콘을 검사한다.

전체 core·CLI, Playwright, 실제 VS Code 검사와 Linux push / Windows 수동 CI를 실행한다. 화면 검사 재시도는 0이다. CI 결과는 [Check 실행 목록](https://github.com/COLLABO-GAMES-DEV/vibe-spec-vscode-extension/actions/workflows/check.yml)의 이 커밋에서 확인한다.

로컬 결과: build·typecheck, core·CLI 781개(플랫폼 조건 제외 7개), 실제 VS Code 73개, 배포 워크플로 계약 6개 통과. Playwright 전체 실행에서 169개가 통과했고, 병렬로 실행한 빌드가 Vite 페이지를 새로고침해 중단시킨 열 삽입 시나리오 1개는 빌드 완료 후 별도로 통과했다. trace의 페이지 이동과 Vite 로그 시각으로 원인을 확인했으며 제품 코드·테스트 단언·타임아웃·재시도 설정을 바꾸지 않았다. CI는 빌드 후 화면 170개를 순서대로 검사한다. VSIX 내부의 버전·README·문서 아이콘·최종 스타일도 확인했다.

## 시험 폴더 정리

시험 폴더에서 표 5개와 문서 30개를 CLI `move` 미리보기·적용으로 최상위 도메인에 합치고 빈 하위 도메인 13개를 CLI로 삭제했다. 도메인 17개가 한 단계로 남았다. 이름 충돌이 없어 이름 변경은 필요하지 않았다.

표·문서·스키마 126개 및 다른 기존 파일의 원문 바이트를 대조했다. 이동 경로·빈 폴더 표시 파일 외에는 변경하지 않았다. 이동한 리소스의 사용처와 61개 기획의 대안·비교 값도 동일하다. `validate`는 기존 오류 1개·경고 18개 그대로이며 `fmt --check`의 변경 대상은 전후 모두 없다. 기존 링크 오류 때문에 명령 종료 코드는 전후 모두 1이다. 상세 경로·검사·해시 기록은 시험 폴더의 `migration/folder-flatten-2026-10-26.md`에만 남기며 실제 데이터는 제품 레포에 포함하지 않는다.
